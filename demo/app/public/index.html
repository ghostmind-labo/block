A window that is only pixels

Scroll. The window beside this text is an html block. It knows nothing of this page but one thing the page lends it: how far, and how fast, you scroll.

The block reaches nothing

It runs in a frame that has no network, no storage and no way to read this page. Its document carries a policy that lets it load only itself. That is the same sandbox Potion uses for the blocks in a note and Relay for a dashboard.

So whatever a block needs from outside, the app has to lend it. Potion lends its notes. Relay lends the things in the house. This page lends its scroll.

One function, declared by the page

The page says what it lends: defineHost({ name: "page", events: ["scroll"] }). Inside the block that becomes page.on("scroll", …). A function the page did not declare does not exist in the block.

Nothing of the page is injected into the frame. The two sides only exchange plain messages, and the page decides what each one means.

Momentum

The window does not play. It answers. While you read slowly its pixels drift a little. Scroll with intent and they pick up speed. Stop, and they calm down again.

Nothing streams and nothing was downloaded for it but a short script: no video, no image.

Half way

You are far enough now that the pixels have somewhere to go. Each one has a place in a shape it has not shown yet.

Keep going and they begin to gather. Scroll back up and they let go.

The mark

By this paragraph the window has settled into a mark, and its label says what it has been all along: a piece of marketing, light enough to pass for a texture.

The mark, the colours and the label are a few numbers in the block's own file. A different sponsor is a different handful of numbers.

What the app counts

The block cannot call out, so it cannot count anything itself. If someone is to know that a window was shown or that its mark was seen, the app counts it, and only what it chooses to.

That is the whole idea: the same sandbox for every app, and each app lending only what it means to lend.
